## 1. 实测证据：入站封死

### 本机网络

| 项 | 值 |
|---|---|
| 网卡 | `ens3`（virtio，OpenStack VM，DMI `RDO / OpenStack Compute`） |
| 内网 IPv4 | `192.168.2.116/16`，网关 `192.168.0.1` |
| 全局 IPv6 | `240e:974:1e00:307:6a::36/128`（RA 下发） |
| **出站** IPv4 | `139.200.108.35`（连测 8 次稳定） |
| **出站** IPv6 | `240e:974:1e00:305::4b9` ← **与本机地址不同段** |
| 邻居 | `192.168.0.1`(网关) `192.168.0.2` `192.168.3.18` —— 同网段还有其他虚机 |
| 元数据服务 | `169.254.169.254` **无响应** |

**出站 IPv6 被改成 `...305::4b9`，而本机地址是 `...307:6a::36`** —— 这是 SNAT（地址池改写），
不是 1:1 映射。IPv6 不需要 NAT 就能直接路由，会被改写只说明**本机在一个 NAT 池后面**。
IPv4 同理，`139.200.108.35` 是共享出口。

### 外部探测（全部来自本机之外）

| 目标 | 探测方 | 结果 |
|---|---|---|
| `139.200.108.35:8787` | check-host.net 6 节点（br/ch/de/hk/id/vn） | 全部 `Connection timed out` |
| `139.200.108.35:8787` | portchecker.io | `status: false` |
| `139.200.108.35:80/443/8080/8443/8765/9000` | check-host.net 各 2 节点 | 全部超时 |
| `139.200.108.35:111`（rpcbind，本机已在监听） | check-host.net 3 节点 | 全部超时 |
| `139.200.108.35:39001`（**当场新起的监听器**） | check-host.net 3 节点 | 全部超时 |

新起一个监听器都不通 —— 说明**不是某个端口被挡，而是整台机器没有入站路径**。

### IPv6 入站：未能验证（工具缺失，如实说明）

`check-host.net` 的 `check-tcp` / `check-ping` / `check-http` **都不接受 IPv6 字面量**（一律 `invalid_url`，URL 形式也不行）；
`portchecker.io` 明确回 `IPv6 is not currently supported`；`ping.pe`、`ipv6scanner.com`、hackertarget（已收费）均无输出。

→ 想确认 IPv6 入站，**只能用手机蜂窝数据（关 WiFi）打开**：
`http://[240e:974:1e00:307:6a::36]:8787/healthz`

## 2. 控制台核查：那个安全组是空的，而且这个账号里没有实例

在天翼云控制台（区域 **贵州3**）逐页核对：

| 页面 | 结果 |
|---|---|
| 你发的安全组详情 `#/vpc/sec/secDetail/de2676f1-…` | 名称 `--`、ID `--`、描述 `--`、企业项目 `--`；**入方向规则 0 条，表格「暂无数据」** |
| 弹性IP 列表 `#/vpc/eip/eipList` | **暂无数据**（0 个） |
| 公网NAT网关 `#/nat/natList` | **暂无数据**（0 个） |
| 资源总览（贵州3） | 弹性云主机 **(0)**、云硬盘 (0)、弹性IP **(0)**、共享带宽 (0)、虚拟私有云 **(1)** |
| 唯一那个 VPC | `192.168.0.0/16`，1 个子网，**创建时间 2026-09-14 08:21:15** |
| AI云电脑（政企版）控制台 `desk.ctyun.cn/cloudB` | 「您已在 1 个资源池开通AI云电脑 **0 台**」，其「虚拟私有云」也**暂无数据** |

**两个关键推论：**

1. **这个账号里没有计算实例**（弹性云主机 0、云电脑 0 台）。所以那个 VPC / 安全组里**没有东西可以被放行**。
2. 本机 DHCP 租约是 **08:04:07** 拿的，此后到 08:40 日志里**没有任何链路/DHCP 事件**；
   而控制台里唯一的 VPC 是 **08:21:15** 才创建的。**创建时间晚于本机联网时间 → 本机不在这个 VPC 里。**

→ **在控制台里加安全组规则/买弹性IP，对本机零作用。** 这就是「安全检查了但服务还是不通」的原因。

## 3. 那要怎么办：四条路（按推荐度）

| # | 方案 | 成本 | 客户侧 | 评价 |
|---|---|---|---|---|
| **A** | **继续用 Tailscale Funnel**（现状） | 免费 | 零配置，只需 URL | ✅ **当前唯一在跑通的，别关** |
| **B** | 买个域名（¥30/年）+ Cloudflare 命名隧道 `cloudflared tunnel` | ¥30/年 | 零配置 | ✅ 地址好看且固定，走 IPv4 就行；缺点：国内访问 CF 绕路 |
| **C** | 买一台**有公网 IP 的云主机**，把网关搬过去 | ¥30–60/月 | 零配置 | ✅ 最正规；**那时你在控制台建的这个 VPC/安全组才真正用得上**；迁移量小（一个 Node 程序 + 一份 YAML + 一个 SQLite） |
| **D** | 用你家宽带的公网 IPv4 做端口映射 | 免费 | 零配置 | ⚠️ 依赖家里不断电不断网；家宽 80/443 通常被封，得用 8787/8443 |

**如果走 C，安全组该这么配**（你问的「怎么设置」）：

```
网络控制台 → 访问控制 → 安全组 → 选你的安全组
→ 入方向规则 标签 → 「快速添加规则」
→ 协议 TCP，端口 8787（或 443/8443），远端 0.0.0.0/0，策略 允许 → 确定
→ 再绑一个弹性IP 到实例
```

⚠️ 但**前提是先有实例**。现在买了弹性IP 也没地方绑。

## 4. 复现命令

```bash
# 本机出站（应稳定返回同一个地址）
for i in $(seq 1 8); do curl -4 -s https://ifconfig.me/ip; echo; done | sort | uniq -c
curl -6 -s https://ifconfig.me/ip

# 外部视角探入站（IPv4 可以，IPv6 不行）
curl -s -H "Accept: application/json" "https://check-host.net/check-tcp?host=139.200.108.35:8787&max_nodes=6"
# → 拿 request_id
curl -s -H "Accept: application/json" "https://check-host.net/check-result/<request_id>"

# 另开一个监听器再探（证明不是"某个端口"的问题）
python3 -m http.server 39001 --bind 0.0.0.0 &
# 然后同样用 check-host 探 39001
```
