## 四、卖点清单（每条都能被验证，别加不能验证的）

- **多路上游调度**：同一模型多路供应，主路异常自动切备路，客户端无感 —— 【填你实际有几路】
- **失败有归因**：429 是限流还是余额不足、要不要重试、退避多久，接口直接告诉你 —— 不用解析错误文本
- **额度与用量自己看得到**：5 小时窗口用了多少、还剩多少、什么时候释放，面板上有
- **成本拆得开**：输入 / 输出 / **缓存命中** 分开计 —— 缓存读比全价输入便宜得多，【填你的倍数】
  很多家把三者合成一个"总 token"，看着便宜，实际算不清
- **不落你的正文**：只存计数与哈希，不存 prompt 内容
- **可对拍**：你的收发字节可以自己算哈希核对，证明我们没改你的数据

## 六、中长文案（公众号 / 落地页，约 350 字）

**标题**：调 Agnes 最怕的不是贵，是不知道它为什么挂

**正文**：

用 API 的人大多算过单价，但很少人算过**失败的代价**。

一次 429 卡住整条流水线，你的 Agent 重试三轮、多花几万 token、最后任务还是没跑完；
上游超时了，日志里只有一句 timeout，你不知道是网络、是模型、还是自己请求写错了。

我们做的事很简单：**把这些不确定变成你可以处理的信息**。

- 同一个模型，我们挂**多路上游**。一条不通自动切下一条，你的代码不用改，也不用自己维护备路。
- 每次失败都带**归因**：限流就给退避时间，余额不足就明确告诉你不该重试，内容被拦就告诉你得改写输入。你的程序可以直接照做，不用再猜。
- **用量和成本在面板上自己看**：请求数、失败分布、缓存命中、每个模型花了多少，全拆开。缓存读取比全价输入便宜得多，【填你的倍数】——这块很多家不给你拆，因为拆开就显得没那么便宜了。

接口完全兼容 OpenAI 协议，**改一个 `base_url` 就能接上**，不用改任何调用代码。

想试的给个招呼，开个试用额度。

## 八、诚信红线（**这几句千万别写**）

| 别写 | 为什么 |
|---|---|
| 「省 40% token」「帮你省一半成本」 | 我们在项目里核过：降损只减少**失败重试**，量级是个位数百分比。写 40% 一次就露 |
| 「比官方便宜 X%」 | 除非你真有稳定价差且能长期撑住。价格战开了就收不回来 |
| 「99.9% 可用率」 | 除非你有真实统计支撑。而且中转站的可用率取决于上游，你保证不了 |
| 「我们从不宕机」 | 没人信，且一旦宕机打脸加倍 |
| 「支持所有模型」 | 你只有 Agnes 一路。写"支持 Agnes 全系模型"就够了，虚报会让来的人失望走 |

**能写、而且比上面那些更有力的**：

- 「多路上游」（结构事实，你确实有）
- 「失败给归因和下一步」（功能事实，代码里有）
- 「缓存命中单独列」（数据事实，你的面板确实拆了）
- 「不落正文、可对拍」（可验证，客户能自己试）

**最后这几条的精髓是：它们客户能自己验证。** 你不需要他信你，只需要他试一次。
这比任何形容词都值钱。

## 九、客户常见提问的答法

**问：你比官方贵吗？**
> 分模型看。我和官方是两条路，直连通了就走直连，成本低；哪天官方线路抖，我自动切到备用线路，
> 代价是我这边成本高一点，但你的任务不会断。**你买的是"不断"，不是单价。**

**问：凭什么信你不改我的数据？**
> 不用信。你请求里带 `x-relay-verify-nonce`，我响应头回一个 HMAC，你对收到的字节重算一遍比对就行。
> 不一致你直接来骂我。

**问：出错了你们的报错能看懂吗？**
> 试一次就知道。同一个 429，别家回你 `Rate limit exceeded`，我回你
> `rate_limited / retry_with_backoff / 2400ms` —— 你的代码可以直接等 2.4 秒重发。

**问：我在别家跑得好好的，为什么要换？**
> 那就别换。等你哪天被一次上游抖动卡住整条流水线、又查不出原因的时候再来。
> 我这儿能告诉你卡在哪一步、是谁的问题。
